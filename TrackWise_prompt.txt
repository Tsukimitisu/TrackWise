Build a full-stack web system called TrackWise using React.js frontend and Laravel backend API.

TrackWise is a flexible OJT, internship, trainee, employee, freelancer, and work-hours tracking system. It must support multiple organizations, multiple user roles, DTR attendance, required hours tracking, daily reports, weekly narrative reports, camera documentation, printable reports, and approval workflows.

TECH STACK:
Frontend:
- React.js
- Tailwind CSS
- React Router
- Axios
- ShadCN UI or clean reusable components

Backend:
- Laravel REST API
- Laravel Sanctum authentication
- MySQL or PostgreSQL database
- Laravel migrations, seeders, models, controllers, policies, form requests, and API resources

Storage:
- Store uploaded documentation photos, DTR photos, profile photos, and documents using Laravel storage.
- Use public storage link for development.

SYSTEM GOAL:
Create a scalable multi-user tracking system that is not limited to OJT only. It should work for:
- OJT students
- Interns
- Trainees
- Employees
- Freelancers
- Volunteers
- Field workers

USER ROLES:
1. Super Admin
- Can manage all organizations
- Can view all users, programs, attendance, reports, and system analytics
- Can activate/deactivate organizations

2. Organization Admin
- Can manage one organization
- Can create programs/tracker setups
- Can add coordinators, supervisors, students, interns, workers
- Can set required hours
- Can view reports and progress

3. Coordinator / Adviser
- Can monitor assigned students or trainees
- Can review reports
- Can view DTR and progress
- Can export/print reports

4. Company Supervisor
- Can validate attendance
- Can approve/reject DTR
- Can approve/reject daily reports
- Can approve/reject weekly narrative reports
- Can add comments and evaluations

5. Student / Intern / Worker
- Can time in and time out
- Can upload camera proof
- Can submit daily reports
- Can submit weekly narrative reports
- Can view completed hours and remaining hours
- Can print DTR and reports
- Can upload required documents

6. Viewer / Auditor
- Read-only access only

CORE MODULES TO BUILD:

1. Authentication and Role-Based Access
- Login
- Register or admin-created accounts
- Logout
- Protected routes
- Role-based sidebar and dashboards
- Laravel Sanctum token/session authentication
- Middleware permissions per role

2. Organization Management
- Create, update, view, activate/deactivate organizations
- Organization types: school, company, training center, agency, freelance team, government office
- Each organization must have separate users, programs, reports, and settings

3. Program / Tracker Setup
Admins can create programs such as:
- BSIT OJT 500 Hours
- Internship 600 Hours
- Employee Training 120 Hours
- Freelancer Work Tracker

Program fields:
- name
- description
- organization_id
- required_hours
- start_date
- end_date
- status
- report requirements: daily, weekly, monthly optional

4. User Program Assignment
- Assign student/intern/worker to a program
- Assign supervisor and coordinator
- Track required hours, completed hours, remaining hours, and completion percentage
- Status: active, completed, dropped, suspended

5. Attendance / DTR Module
Student can:
- Time in
- Time out
- Upload time-in photo
- Upload time-out photo
- Add remarks
- Optional GPS latitude/longitude

System must:
- Calculate total rendered hours
- Deduct break minutes
- Prevent duplicate time-in for same date
- Prevent time-out without time-in
- Prevent editing approved attendance unless admin allows correction
- Mark status: present, late, absent, undertime, pending, approved, rejected
- Allow supervisor approval

Printable DTR must include:
- Student name
- Organization
- Program
- Required hours
- Completed hours
- Remaining hours
- Date
- Time in
- Time out
- Total hours
- Remarks
- Approval status
- Supervisor signature placeholder
- Coordinator signature placeholder

6. Camera Documentation Module
- Upload or capture photo documentation
- Attach photos to attendance, daily reports, or general documentation
- Add caption
- Store date/time taken
- Optional GPS location
- Preview uploaded images
- Filter documentation by date/program/status

7. Daily Report Module
Student submits:
- report_date
- tasks_done
- tools_used
- problems_encountered
- learnings
- attached photos
- status: draft, submitted, approved, rejected, needs_revision

Supervisor/coordinator can:

8. Weekly Narrative Report Module
Student submits:
- week_number
- start_date
- end_date
- summary_of_activities
- skills_learned
- challenges
- reflection
- attached documentation
- status

Optional:
- Auto-generate weekly narrative draft from approved daily reports.

9. Approval Workflow
Create reusable approval logic for:
- attendance logs
- daily reports
- weekly reports
- uploaded documents
- evaluations

Approval statuses:
- draft
- submitted
- pending
- approved
- rejected
- needs_revision

Store approval history in approval_logs table.

10. Notifications
Notify users when:
- DTR is approved/rejected
- Daily report is approved/rejected
- Weekly report is approved/rejected
- Missing time-out
- Weekly report is due
- Required hours completed
- Document needs revision

11. Document Checklist
Allow students/workers to upload required documents:

- Endorsement letter
- MOA
- Waiver
- Parent consent
- Certificate
- Evaluation form
- Other custom documents

Admin can mark documents:
- pending
- approved
- rejected
- needs_revision

12. Evaluation Module
Supervisor can evaluate student/worker using scores:
- attendance_score
- performance_score
- communication_score
- technical_score
- professionalism_score
- comments

13. Printable / Export Reports
Create printable pages or PDF-ready views for:
- DTR
- Daily report
- Weekly narrative report
- Monthly summary
- Completion summary
- Evaluation form

Use browser print first. Make the layout clean and formal.

IMPORTANT BUSINESS RULES:
- Users only see data from their own organization unless they are Super Admin.
- Students only see their own attendance, reports, documents, and progress.
- Supervisors only see assigned users.
- Coordinators only see assigned users or users under their organization.
- Completed hours should update only from approved attendance logs.
- Rejected attendance must not count toward completed hours.
- One attendance record per user per date unless admin enables multiple sessions.
- Reports can be edited while draft or needs_revision, but not after approval.
- All approvals must create an approval_logs record.
- Uploaded files must be connected to the correct user_program.
